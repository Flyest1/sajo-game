# A. 기술

## A-1. 실제 결함

### ① `renderBattle(light)`의 `light` 인자가 미사용 — 죽은 매개변수

`src/game.js:1646`에서 `light`를 받지만 본문에서 한 번도 참조하지 않는다.
호출부 약 20곳(특히 `strike()` 내부에서 타격 1회당 2회)이 "가벼운 렌더"를 기대하며
`renderBattle(true)`를 넘기지만, 실제로는 **매번 전체 맵 SVG 문자열을 재생성해
`svg.innerHTML = s`로 통째로 교체**한다.

20×15 맵이면 타일 300개 + 유닛 + 하이라이트 + 의도 아이콘을 공격 한 번마다 두 번
파괴·재생성한다. 유닛의 `<image href="...webp">`와 `<clipPath>`도 매번 새로 생성되며,
애니메이션 코드가 `document.getElementById('ug-'+uid)`를 매번 재조회해야 하는 것도
이 구조 때문이다. 모바일 프레임 드랍의 1순위 원인.

**대응**: `light === true`면 유닛 `<g>`의 transform·HP 바만 갱신하는 부분 렌더 경로를 실제로 구현한다.

### ② 적 의도 표시가 아군 행동 후 갱신되지 않음

`refreshEnemyIntents()` 호출부는 네 곳뿐이다.

| 위치 | 시점 |
|---|---|
| `game.js:1247` | `startPlayerPhase` |
| `game.js:1380` | `startBattle` |
| `game.js:1142` | 성문 파괴 |
| `game.js:638` | 간파 교란 |

**아군이 이동·공격·사망해도 갱신되지 않는다.** 위협 *범위*(`enemyThreatTiles`)는 렌더 시점에
`moveRange`를 다시 돌려 최신이지만, 유닛 위 의도 화살표와 정보창의 `intentText()`는
페이즈 시작 시점의 낡은 표적을 계속 가리킨다.

보스 전조는 표적 고정이 의도된 설계지만, 일반 적의 의도는 게임의 핵심 전술 정보인데
내 턴 첫 이동 직후부터 잘못된 정보를 표시한다.

**대응**: `finishUnit()`과 유닛 사망 처리 뒤에 `refreshEnemyIntents()`를 호출한다.
(보스 `pending` 계획은 `ensureBossActionPlan`이 이미 보존하므로 전조는 영향받지 않는다.)

### ③ 청크 분리가 초기 페이로드를 줄이지 못함

`campaigns.js:8`의 `import.meta.glob('./data/stages_*.json', {eager:true})`가 13개 캠페인을
정적 import하므로, 빌드 결과 `dist/index.html`이 `campaign-data`(390KB)를
`modulepreload`로 참조한다.

즉 **타이틀 화면 하나 띄우는 데 전 캠페인 데이터(390KB, gzip 119KB)를 내려받고 파싱**한다.
청크는 나뉘었지만 병렬 요청으로 쪼갠 것일 뿐 지연 로딩이 아니다.

**대응**: `eager:false`로 바꾸고 캠페인 선택 시점에 동적 `import()`. 초기 JS를 1/3 이하로 줄일 수 있다.

### ④ 공격 1회당 localStorage 전체 세이브 쓰기 2~3회

`save.js:118` `writeV3()`는 호출마다 `normalizeV3()`로 전체 세이브를 딥클론·정규화한 뒤
`JSON.stringify`한다. 그런데 이를 호출하는 곳이

- `bumpMastery()` — 무공 사용 시마다
- `saveStats()` — 격파·필살 시마다
- `unlockAchv()` — 업적 해금 시

이고, 각각 레거시 키(`kimyong_mastery` 등)에 **한 번 더** 쓴다.
동기 스토리지 쓰기가 전투 연출 도중 매 타격마다 발생한다.

**대응**: 세션 중에는 메모리에만 누적하고 전투 종료(`showVictory`/`showDefeat`) 시 일괄 flush.

### ⑤ `migrateLegacy()`가 모듈 최상위에서 실행 — 부팅 전체가 localStorage에 의존

```js
// src/game.js:57
let V3STORE = migrateLegacy();
```

모듈 평가 시점에 `localStorage.getItem/setItem`을 호출하며 `writeV3`에는 try/catch가 없다.
**사파리 프라이빗 모드, 사이트 데이터 차단, 저장소 할당량 초과 시 모듈 초기화가 던져지고 화면이 백지가 된다.**

게임 내부의 개별 저장 호출은 이미 try/catch로 감싸져 있는데 정작 부팅 경로만 무방비다.

**대응**: `writeV3`/`migrateLegacy`를 try/catch로 감싸고, 실패 시 인메모리 전용 스토어로 폴백해
"저장 불가" 안내만 띄운 뒤 플레이는 계속되게 한다.

### ⑥ 순수 모듈에 노드 단위 테스트가 없음

`combat-rules` · `combat-resolution` · `mastery` · `pathfinding` · `battle-objectives`는
DOM·세션 의존이 전혀 없는 순수 함수인데, 검증은 전부 Playwright `page.evaluate`로
브라우저 + dev 서버를 띄워서 한다. 풀 스위트가 3.4분.

`node --test`로 이 다섯 모듈만 뽑으면 수십 ms에 끝나고, 경계값(0데미지, floor 클램프,
guard 파훼 경계)을 훨씬 촘촘히 덮을 수 있다. **모듈을 순수하게 분리한 U7 작업의
이득 대부분이 아직 회수되지 않았다.**

# B. 게임성

## B-1. 데미지 공식이 0 데미지 교착을 만든다 ★최우선

```js
// src/game.js:404
dmg = max(0, round(atk × mult) + 상성×2 + 협공 + 인연 + 장비atk − 방어 − 지형def)
```

**곱연산 뒤 정액 감산**이고 하한이 `Math.max(0, ...)`다. 즉 **최소 데미지 보장이 없다.**
방어가 높은 적에게는 영구히 0이 뜬다.

`npm run balance`가 직접 보고하는 값(`처치 99.0R` = 데미지 0):

```
std   사조 곽정(L6)   vs 구양봉    : 아군 99.0R | 적 1.5R
hero  진최종 곽정(L14) vs 금륜법왕  : 아군 99.0R | 적 4.3R
hero  진최종 곽정(L14) vs 구양봉    : 아군 78.2R | 적 4.7R
```

진최종전 보스를 주인공이 1:1로 절대 죽일 수 없다. 협공·인연·파훼·간파·합동오의를
전부 동원해야 뚫리도록 설계한 것이라면 의도적일 수 있으나, 그렇다면
**"기본 타격이 0"이라는 피드백을 플레이어가 읽을 방법이 없다.** 화면에는 그냥 `0`이 뜬다.

부가 문제: 호신강기가 있을 때만 `Math.max(1, ...)`로 하한이 걸려 있어
**강기 보유 보스가 강기 없는 잡몹보다 오히려 때리기 쉬운** 역전이 발생한다.

또한 시뮬의 이상치 탐지는 `양측 > 12R`(교착)만 잡고 **한쪽만 99R인 일방 무력 상태는 통과**시킨다.
탐지 규칙 자체에 구멍이 있다.

**대응**: 최소 데미지 1~2 보장, 또는 정액 감산 대신 감쇠 비율(`atk²/(atk+def)` 계열)로 전환.
동시에 `balance_sim.mjs`의 이상치 규칙에 "일방 99R" 케이스를 추가한다.

## B-2. 후반 경험치 인플레이션 — 난이도 곡선 붕괴

```js
// src/game.js:360   적 레벨 = 진행도 카운터
lvl: curCh().no * 3
// src/game.js:3152  캠페인의 no = 클리어한 전투 수 + 1
return { no: battles + 1, ... }
// src/game.js:673   격파 경험치
grantExp(a, 30 + Math.max(0, (d.lvl - a.lvl)) * 4 + (d.boss ? 40 : 0));
```

적 `lvl`은 **실제 능력치와 무관한 진행도 카운터**인데 그것이 경험치 공식을 직접 굴린다.
확장 적용 후 실제 전투 수:

| 캠페인 | 전투 수 | 최종 전투 적 lvl |
|---|---|---|
| 사조영웅전 | 19 | 57 |
| 신조협려 | 14 | 42 |
| 의천도룡기 | 18 | 54 |
| 천룡팔부 | 21 | **63** |

천룡팔부 종반에 아군이 Lv.20이면 잡몹 1킬 = `30 + (63−20)×4 = 202` 경험치 = **레벨 2개**.
반면 적 스탯은 `characters.json` 고정값이라 전혀 오르지 않는다.

결과적으로 후반이 급격히 쉬워지고 B-1의 0 데미지 문제도 저절로 해소되어
**난이도 곡선이 U자가 아니라 절벽**이 된다.

**대응**: 적 `lvl`을 스테이지 데이터에 명시하거나, 경험치 격차 보정에 상한(`min(15, 격차)`)을 둔다.

## B-3. 상점이 무의미해진다 — 장비가 배수 밖에서 더해짐

`eqAtk`는 `round(atk × mult)` **뒤에** 더해지므로 무공 배수(1.35~2.0)의 혜택을 못 받는다.

| 획득 | 무공 1타 기여 |
|---|---|
| 의천검 (3600냥, `atk +5`) | **+5** (고정) |
| 레벨업 1회 `str +1` | **+1.9** (항룡십팔장 1.9배 기준) · 영구 · 전 무공 적용 |

3600냥 최고급 무기가 레벨 3개보다 못하다. 그런데 B-2 때문에 후반에는 킬당 레벨 2개가 들어온다.
반대로 방어구는 감산이 정액이라 상대적 가치가 유지되고, 특히 적의 `def`는 내 데미지를 0으로
만드는 결정적 스탯이다.

결국 **공격 장비 < 방어 장비 ≪ 레벨업**이 되어 거점 상점·엽전 경제·전리품이 전부 껍데기가 된다.

**대응**: `(atk + eqAtk) × mult`로 장비를 배수 안에 넣거나 곱연산 계수로 전환.

## B-4. 무공 49종이 기계적으로는 3종

`skills.json` 49개 무공의 차이는 `mult`(1.35~2.0)와 `hit`(0~30)뿐이다.
예외는 중독 4개, 2연격 1개(좌우호박), 회복 2개.

**사거리 변화 없음 · 범위기 없음 · 이동/밀치기 없음 · 디버프 없음 · 지속효과 없음.**

원작 무공 49종을 고증한 노력에 비해 전장의 선택은 "제일 배수 높은 것"으로 수렴한다.
3개 편성(`skillLoadouts`)과 연계(`comboStep`, 다른 초식을 이으면 +8%/단, 최대 +24%)가
이를 구하려는 장치인데, **연계의 진짜 가치는 데미지가 아니라
`enemyMartialCounter`의 `combo` 파훼 조건 충족**에 있다.

이 인과(연계 → 간파 → 보스 초식 취소)가 이 게임에서 가장 잘 설계된 루프인데,
정작 데미지 숫자에 묻혀 잘 드러나지 않는다.

**대응**: 무공 3~5종에 사거리/범위/상태이상을 부여해 "상황별 선택"을 만든다.
연계 → 간파 인과를 전투 예측 화면에서 명시한다.

## B-5. 아군과 적의 설계 비대칭

`enemy-martials.js` + `boss-actions.js`로 주요 적 20명에게 line / cone / cross / radius
범위기 + 2단계 축력 + 예고 타일 + 파훼 조건을 부여했다. **이 게임에서 가장 좋은 부분이다.**

그런데 아군의 응수 수단은 "한 칸 옮기고 한 명 때리기"뿐이다.
예고 범위 회피 외에 능동적으로 개입할 방법이 인연 합동오의(A랭크 페어당 전투 1회) 정도다.
**적은 3차원, 아군은 1차원으로 싸운다.**

## B-6. 사망 페널티가 사실상 없음

// src/game.js:2098 — alive 필터가 없다
function applyRoster(){
  for(const u of B.units.filter(u => u.team === 'P')){ ... r.lvl = u.lvl; r.exp = u.exp; ... }

쓰러진 협객도 획득 경험치를 그대로 가지고 다음 전투에 만피로 복귀한다.
패배는 수령 사망 / 보호 대상 사망 / 전멸일 때만이다.

캐주얼 지향이라면 합리적 선택이지만, 그 결과 **"유닛을 잃지 않는다"는 SRPG의 핵심 긴장이
통째로 사라진다.** 유일한 대가는 `flawless` 업적 하나뿐.

**대응**: 최소한 협객 난이도에서만이라도 다음 전투 능력치 페널티, 부상 상태 1전투 지속,
치료비 등 완충 페널티를 둔다.

## B-7. 적 AI의 전술 결함

`enemy-ai.js`:

- **탐욕적 공격 강제** — 공격 가능한 수가 하나라도 있으면 무조건 공격한다(`if(best) return best`).
  반격 데미지는 점수에서 `×0.5`로 감산되지만 이는 *공격안들끼리*의 비교일 뿐,
  **"공격하지 않고 대기·후퇴"와는 비교되지 않는다.** 적이 반격에 죽는 자리로 계속 걸어들어온다.
- **접근 시 지형·위험 무시** — 공격 불가 시의 이동은 순수 맨해튼 거리 최소화다.
  `terrainAt`(회피·환경 위험)은 공격 점수에만 쓰이고 접근 이동에는 쓰이지 않는다.
  그래서 **R22의 불길·낙빙·독무 타일 위로 태연히 걸어간다.**
  환경 시스템을 만들어 놓고 AI가 그것을 모른다.
- 아이템 미사용, 수비 태세 없음, 집중 공격 조율 없음.

**대응**: 접근 이동 후보 점수에 `terrainAt`를 반영하고, 최선 공격안의 기대 이득이
예상 반격 손실보다 작으면 대기/후퇴를 선택하게 한다.

## B-8. 숙련도 전 모드 공유 = 난이도 우회 통로

`SKILL_USE`는 프로필 전역 값이라 무한 모드·강호유람에서 무한정 파밍할 수 있고,
極(70회) 도달 시 **위력 +16%p · 명중 +8 · 기 소모 −2**가 캠페인에 그대로 적용된다.

문서에 "전 모드 공유"로 명시된 의도된 기능이지만,
무한 모드 30분이면 협객 난이도의 적 +15% 보정을 상쇄하고도 남는다.

## B-9. 출전 편성이 자동 완충

`showDeploy()`가 파티를 캡까지 자동으로 채우고, 대부분 스테이지에서 파티 ≤ 캡이라
선택지가 없다. 편성 화면이 확인 버튼으로만 기능한다.
