# 강호의 별 v3 통합판 — 실행 계획

> 조사 기준: `docs/V3_RESEARCH.md`
> 원칙: 정사 본편 하나, 공통 엔진 하나, 비파괴 세이브 이관, 창작 범위의 명확한 표기

## 2026-07-25 구현 상태

| 범위 | 상태 | 이번 기반 작업 |
|---|---|---|
| U0~U2 | 기반 완료 | v3 명칭·정보구조, 통합 저장 이관, 캠페인 manifest, 목표 스키마 |
| U3~U4 | 1차 완료 | 클래식 19전의 공통 캠페인화, 통합 진입점·이어하기, 두루마리형 PC/모바일 UI |
| U5 | 1차 완료·전투 확장 진행 | 본편 4작품의 정사 연결 장면 31개(사조 8·신조 8·의천 7·천룡 8) 적용. 신규 전투·선택 분기는 후속 |
| U6 | 1차 완료 | 데이터/그래프/목표 검증, 데스크톱·모바일 Playwright 스모크, CI 연동 |
| R13~R15 | 플레이 가능 1차 | 적 의도·위험, 점거·탈출·비살상 제압, 호신/파훼, 4대 종장 2단계 보스, 무공 편성·연계·합동 오의 |
| R16 | 1차 완료 | 수묵 3중 맵·시간대 변화, 전 인물 5표정, 무공/합동/보스 컷인, 먹선 궤적, 저효과 UI |
| R17 | 플레이 가능 1차 | 4인·10노드·기연/객잔/전투/고수·시드 공유·중단 저장 |
| R18 | 플레이 가능 1차 | 협·정·세와 일부 문파 관계, 선택 직전 스냅샷 기반 강호 회고 |

`1차`는 구조와 대표 콘텐츠가 실제로 동작한다는 뜻이며, 모든 캠페인에 전용 패턴·평판·신규 전투가 배치되었다는 뜻은 아니다. 외부 팬픽 원문을 확인할 수 없는 경우에는 제목이나 2차 요약만으로 내용을 지어 넣지 않는다.

## 제품 구조

```text
강호의 별
├─ 강호연대기
│  ├─ 천룡팔부
│  └─ 사조삼부곡: 사조 → 신조 → 의천
├─ 강호외전
│  ├─ 월녀검
│  ├─ 오절전기·활사인묘·풍릉의 등불
│  └─ 명교잔화
├─ 도전
│  ├─ 강호유람
│  ├─ 천하논검
│  ├─ 전투 수수께끼
│  └─ 영웅집결 무한 모드
├─ 회상
│  └─ 초대판 회상록 19전
└─ 강호록
   ├─ 인물·문파·무공·사건 연표
   ├─ 업적·전적
   └─ 판본 이문·게임 창작 표기
```

## U0~U6 — 전체 통합

### U0. 정체성·정보 구조

- `v2`, `신규`, `베타`, 과거 R단계 문구 제거
- 새 게임은 강호연대기로 연결
- 캠페인 카드에 `원작 본편`, `원작 단편`, `원작 공백 기반 창작`, `비정사 도전` 배지 표시
- 천룡팔부와 사조삼부곡의 독립성, 사조 3권의 세대 계승을 지도에서 시각화

완료 조건: 첫 화면에서 플레이어가 클래식과 리부트 중 무엇이 본편인지 고민하지 않는다.

### U1. v3 세이브

```js
{
  version: 3,
  profile: { settings, achievements, stats, mastery, codex, reputation },
  campaigns: { [id]: CampaignState },
  challenges: { endless, roam, trials },
  legacy: { classicV1, importedV2 },
  lastSession: { mode, campaignId, at }
}
```

- 기존 `kimyong_srpg_save_v1`, `kimyong_v2_*`, 업적·숙련·설정을 읽어 최초 1회 복사
- 원본 키는 자동 삭제하지 않음
- 내보내기 파일에 스키마 버전·검증 결과 포함
- 잘못된 세이브는 전체 실패 대신 해당 구획만 격리

완료 조건: v1 클래식, v2 캠페인, 신규 사용자, 일부 손상 세이브의 자동 테스트 통과.

### U2. 캠페인 manifest·데이터 스키마

- 하드코딩된 `CAMPAIGNS`와 캠페인 카드 목록을 `campaigns.json`으로 이동
- 그룹·연대·정사 등급·선행 조건·계승·추천 레벨·기능 플래그 정의
- 스테이지 목표를 공통 구조로 확장: 섬멸·방어·구출·탈출·제압·점령·결투·동시 목표
- 그래프 도달성, 잘못된 플래그, 막힌 엔딩, 필수 인물 부재 검증

완료 조건: 새 캠페인은 JSON 등록만으로 선택 화면과 세이브 허브에 나타난다.

### U3. 런타임 통합

- `G`, `V2`, `ENDLESS`의 역할을 `Session`과 `BattleContext`로 정리
- 전투 엔진이 모드 이름 대신 전달된 규칙·목표·보상만 사용하도록 변경
- 클래식 19장을 공통 캠페인 그래프에 연결
- 장비·인연·난이도·숙련·전투 예측을 모든 스토리 모드에서 동일 적용

완료 조건: 전투 핵심 경로에서 `if (V2)` 식의 모드별 기능 차단이 남지 않는다.

### U4. 화면 흐름·UI

- 타이틀 → 강호연대기 → 권/막 지도 → 출전 → 전투 → 전후 선택의 일관된 흐름
- 최근 플레이 한 번에 이어하기
- 시대 두루마리형 캠페인 지도와 정사 등급 배지
- 모바일 하단 행동바, 키보드 포커스, 색상 외 문양을 병용한 위험 정보

완료 조건: 360px 모바일과 1920px PC에서 핵심 버튼이 겹치지 않고 키보드만으로 시작·저장·전투 가능.

### U5. 콘텐츠 이관·확장

- `V3_RESEARCH.md`의 누락 사건을 talk/choice/battle로 배치
- 사건을 모두 전투화하지 않고, 인물 변화가 필요한 지점만 조작전으로 구성
- 정사 결말과 IF 결말의 배지·색·해금 보상 분리
- 개발 로드맵 문구를 세계관 대사에서 제거

완료 조건: 본편 네 작품의 40/40/40/50회 핵심 사건 체크리스트에 미설명 공백이 없다.

### U6. 품질 기준

- 데이터 검증과 밸런스 시뮬레이션 강화
- Playwright 브라우저 스모크 테스트 추가
- 신규 시작, 이어하기, 분기, 패배, 보스 단계, 세이브 이관, 오프라인 빌드 자동화
- README·SYSTEMS·SCENARIO·PLAN을 v3 기준으로 동기화

## R13~R18 — 게임성 개선

### R13. 읽을 수 있는 전장

- 적의 다음 행동·목표·위험 범위 표시
- 행동 확정 전 예상 결과와 적 반격/특수효과 표시
- 구출·탈출·제압·거점·동시 점령·화재 확산·호위 목표
- 보스 패턴 타임라인과 전투 중 승리 조건 변경

### R14. 파훼·호신강기

- 강적에게 `호신`과 `기세` 게이지 부여
- 상성·측후면·제어·지형·인연 협공으로 파훼 수치 축적
- 호신 붕괴 시 한 턴의 파훼 창과 전용 연출
- 보스 2~3단계 패턴과 단계 전환 대사

### R15. 무공 편성·연계·합동 오의

- 출전 시 무공 3개 + 내공 1개 편성
- 초식 태그와 순서 연계
- 인연 A 및 특정 사건 해금 시 합동 오의
- 무공을 늘리기보다 캐릭터별 역할·리듬을 구분

### R16. 수묵 전장·UI 폴리시

- 전경·중경·원경 레이어, 날씨와 시간대의 전투 변화
- 먹선 궤적, 금색 파훼, 붓글씨 무공명, 보스 낙관
- 컷인과 표정은 데이터 기반 SVG로 생성
- 저효과 모드와 화면 흔들림·섬광 강도 옵션

구현 상태: 코드 생성 SVG만 사용해 전경·중경·원경을 기존 전장 위에 합성한다. 맵 스크롤에 서로 다른 비율로 반응하며 시간대는 3턴마다 이동한다. 기존 초상 데이터에서 평상·분노·부상·각성·미소를 자동 생성하고, 대사 분위기 또는 명시적 `expr` 값으로 선택한다. 무공·A급 합동 오의·보스 등장/단계 전환에는 반신 컷인과 낙관을, 실제 타격에는 유형별 먹선 궤적을 사용한다. 저효과 모드는 이 동작들과 날씨 입자를 생략한다.

### R17. 강호유람

- 10~15노드 로그라이크 원정
- 전투·객잔·기연·상점·문파 사건·고수 도전
- 4인 시작, 비급·보물 빌드, 시드 공유
- 완주 영웅의 별호·흉터·전설을 프로필에 기록

### R18. 평판·문파·역사 회귀

- `협(俠)·정(情)·세(勢)` 평판
- 문파 관계와 인물별 신뢰
- 결말 뒤 이전 분기점으로 돌아가는 연표형 회귀
- 이미 본 대사는 요약 선택, 미확인 분기는 강조

## 구현 순서와 릴리스 게이트

1. U0~U2를 먼저 구현해 데이터와 세이브 기반을 고정한다.
2. U3~U4로 초대판과 리부트를 실제로 하나의 제품 흐름에 합친다.
3. U5는 사조 → 신조 → 의천 → 천룡 순으로 보강하되 플레이 순서는 역사순으로 표시한다.
4. U6 자동 테스트가 갖춰진 뒤 R13~R15 전투 규칙을 넣는다.
5. R16을 적용하고 성능 기준을 통과한 뒤 R17~R18 메타 시스템을 추가한다.

각 단계는 `데이터 검증 → 단위/스모크 테스트 → 프로덕션 빌드 → 모바일 확인`을 통과해야 다음 단계로 진행한다.
